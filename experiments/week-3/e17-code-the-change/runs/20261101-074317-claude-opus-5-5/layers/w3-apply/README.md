OpenSpec's own `openspec-apply-change` skill, as `openspec init --tools claude` generates it in OpenSpec 1.15.0 (MIT, Fission AI). Copied unchanged on 1 November 2026, for e17 only (step 4, the coding agent). Kept out of `w3-openspec` so the planning steps (e14, e16) never load an implementation skill. Regenerate it when the image's OpenSpec version changes; `openspec-propose` in `w3-openspec` came from the same generation and is identical.

`settings.json` allows the skill itself (`Skill(openspec-apply-change)`). Without it, the first e17 run (1 November) was refused the skill in batch mode: "Permission to use Skill has been denied because Claude Code is running in don't ask mode". The skill declares `allowed-tools` in its frontmatter; `review-change`, which declares none, loads in batch mode without a rule (INFERRED as the difference).
